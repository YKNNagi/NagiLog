# NagiLog

## 概要

技術学習の備忘録、チートシート、デバッグ・問題解決の思考、
開発の成長過程を記録する個人技術ブログ。

ポートフォリオとして一般公開し、
「何を学んだか」だけでなく「どのように考えたか」を伝えることを目的とする。


## 開発方針

本プロジェクトでは、AIをコード生成の代替ではなく、
設計・レビュー・学習支援として活用する。

基本的な開発サイクルは、

**要件定義 → 設計 → 小さく実装 → 動作確認 → テスト → レビュー**

とする。


### 役割分担

#### 開発者（nagi）

- 要件定義・仕様決定
- 設計判断
- 実装
- テスト
- 最終的な採用・不採用の判断


#### ChatGPT

- 学習サポート
- 要件・設計・実装工程の小さな単位への分解
- Django・Python等の技術解説
- 実装時のヒント・デバッグ支援


#### Codex

- 要件の抜け・矛盾チェック
- 設計レビュー
- 影響範囲レビュー
- 実装したコードのレビュー
- テスト観点の漏れチェック
- 可読性を目的としたコード整形

コード整形では、インデント・改行・空行・import等の整理のみを行い、
既存のロジック・仕様・処理内容は変更しない。

AIから提示された案をそのまま採用するのではなく、
プロジェクトの目的・学習範囲・実装コストを考慮し、
最終的な判断は開発者自身が行う。


## 利用者

### 管理者

- 管理者は1名のみ
- 記事・タグを管理する
- 管理操作はsuperuserのみ可能


### 一般閲覧者

- ログイン不要
- 記事・タグの閲覧のみ可能
- 管理操作は行えない


## 現在実装済み

### 記事

- 記事一覧
- 新規作成
- 編集
- 削除
- タグ付与
- 作成日時・更新日時
- 新しい記事を優先して表示
- 固定記事
- 固定記事を記事一覧の先頭に表示
- 固定記事が存在する場合、通常操作から別の記事を固定できない
- 固定記事自身は固定解除可能


### タグ

- ArticleとManyToManyで関連付け
- 管理者のみ作成可能
- 半角英数字のみ使用可能
- 大文字・小文字を区別せず重複を禁止
- 記事作成・編集時に既存タグを選択可能
- タグによる記事絞り込み


### 認証・認可

- 一般ユーザー登録なし
- 未ログインユーザーはRead Only
- 記事・タグの管理操作はsuperuserのみ可能
- サーバー側で管理Viewへのアクセスを制御
- 管理画面への直接POSTもアクセス制御
- 管理用リンクはsuperuserにのみ表示


### UI・操作補助

- 記事タイトルの文字数表示
- JavaScriptによるタグ選択UI
- 記事作成・編集・削除画面からのキャンセル導線


### テスト

Django TestCaseを使用し、以下を自動テストしている。

- 記事の作成・編集・削除
- ArticleForm
- タグ作成
- タグのバリデーション
- タグによる記事絞り込み
- 記事の表示順
- 固定記事のフォーム制御
- 固定記事の保存結果
- superuserによるアクセス制御
- 未認証ユーザーによる管理操作の拒否

現在、**66件のテストがすべて成功**している。


## TOP画面

- タグ絞り込み
- 固定記事を最優先で表示
- 通常記事を新しい順に表示
- 管理者ログイン時のみ管理操作を表示


## 安全性

- Form validationによる入力値の検証
- Djangoの自動エスケープを維持
- 状態変更にはPOST + CSRF対策を使用
- 管理操作はサーバー側でもアクセス制御
- Django Formのdisabledを利用し、不正な固定記事指定を通常操作から防止
- テストによってアクセス制御および保存結果を確認

## 本番環境

以下を本番公開時の要件とする。

- PostgreSQL
- nginx
- HTTPS
- DEBUG=False
- SECRET_KEY等の秘密情報をリポジトリへ含めない
- ALLOWED_HOSTSを制限
- Djangoのデプロイチェックを実施
